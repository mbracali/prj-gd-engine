# Hair collision study (GD05-113), 2026-11-16

The owner on the current build: "The physics of the hairs are weird, they are way better now, but I can see some hair clipping inside the characters. Maybe we need to review how rigid bodies are colliding." This is a study only. No code was changed, and nothing was built or run.

Sources:
- The port's `engine/src/char/rig.cpp`, `char_objects.cpp/.h`, `render/scene_gpu.cpp` and `app.cpp`.
- RB's XEX through the analysis export plus a headless `DumpAsm` of 0x823392A0 and 0x82337180.
- Every non-crowd character milo under `extracted/ark/char`, read with `tools/milo.py`: 185 CharHair, 536 strands, 1,539 points and 1,599 CharCollide.

Tags: [C] confirmed in code or data, [I] inferred.

## Root cause

**The port runs no hair collision at all for RB [C].** The rig still has GH2's per-point `type` / `collide` fields. RB's rev 9 point (load 0x823372A0) has neither: it has pos, bone, length, radius (+0x64), outer_radius (+0x68) and side_length (+0x6c), plus a runtime `collides` list at +0x50 that the load clears.
- So `pt.collide` is empty and `q.collide = -1` (rig.cpp:495), which means the `if (p.collide >= 0)` block (rig.cpp:1089) never runs.
- CharCollide objects are not nodes of the port's skeleton, because `gfx::transOf` (scene_gpu.cpp:20) has no CharCollide. They could not be placed even if they were looked up.

## How RB does it

**Hookup** (`hookup`: CharHair handler 0x82339568 -> 0x823392A0; called from the character's `sync_objects`, `char_objects.dta:1042`, and from 0x823399D8):
- It collects every CharCollide in the hair's directory: the character, with its outfit pieces merged.
- For each strand with a root, it clears each point's list.
- For each collide `c` it checks `strand.hookup_flags (+0x80) & c.flags (+0xc4)`. When that is non-zero it walks the points with `L += point.length`. A point gets `c` when `c.worldRadius (+0xc0) + max(radius, outer_radius) + L > |c.worldPos - root.worldPos|`, measured at hookup time [C, asm 0x823393E4..0x823394B4].

**Collide world radius** (`compute_radius`, 0x8232DE80 -> 0x8232DB30) is `|collideWorldXfm * (0, radius, 0) - collideWorldPos|`, that is, the local radius times the collide's world y scale [C]. `DEFORM_COMMON` sends it to every CharCollide after the body deform (`char_objects.dta:802`). The constructor (0x8232D5A8) leaves +0xc0 unset, and the load fills only shape +0xb4, radius +0xb8, length +0xbc and flags +0xc4 [C].

**Simulation step** (0x82335B10, one call per poll from CharHair::Poll 0x82337180; strand 0x88 bytes, point 0x70 bytes) runs each point from root to tip, in this order:
1. `pos += vel`, then `z += gravity * -3.8582678 * 60 / rate^2` [C].
2. **Neighbour slack**: only when `side_length >= 0`. The neighbour is the same point index on strand `(s + 1) % n`. If `d^2 < (side - min_slack)^2` or `d^2 > (side + max_slack)^2`, then with `k = t^2 / (t^2 + d^2) - 0.5` the point's pos moves by `k * delta` and the neighbour's **velocity** by `-k * delta` [C].
3. **Length**: `k = length / |pos - prev| - 1`. The previous point's vel gets `+= d * k * (-0.5 * weight)`, and `pos += d * k` [C]. This is the same as the port.
4. **Rest**: `rest = prev + frameY * length`. The frame is strand mat2 (+0x50) times the root parent's world [C], the same as the port. Torsion slerps the point's stored orientation (+0x30, 4 floats) by `torsion` (FUN_82197BA8) [C call / I slerp].
5. **Collisions**: for each collide in the point's list, `o = pos - c.worldPos`, then by `c.shape` [C]:
   - 0: error (notify), no test.
   - 1: outside a sphere, `inner = point.radius + c.r`, `outer = point.outer_radius + c.r`.
   - 2: inside a sphere, `inner = c.r - point.radius`, `outer = c.r - point.outer_radius`.
   - 3: outside a **capsule**. `t = dot(o, c.xAxis)` is clamped to `[0, c.length]` and `o -= xAxis * t`, then shape 1's test runs.
   - 4: inside the same capsule, then shape 2's test.
   - Over 4: skipped.
   - Test: if `outer <= inner` (no band), a hard push of pos to `inner` along `o`. Otherwise, past `inner` the pos is pushed to `inner` and the orientation set to the push direction. Between `inner` and `outer` only the orientation slerps toward the direction by `(outer - d) / (outer - inner)`. The outer band never moves the position.
6. The bone is placed (prev -> pos, orientation from step 4/5).
7. `vel = stiffness * (rest - pos) - friction * (oldNv - nv) + inertia * (pos - oldPos)` [C]. This is the same as the port.

Answers to the questions:
- **Per point or per segment**: collisions are tested per point only [C]. A segment between two points can pass through a collide in RB too, so don't add segment tests.
- **Order**: integration, then slack, then length, then collision, then bone, then velocity. The collision wins over the length constraint [C].
- **Iterations**: one pass a poll. There is no iteration loop and no substeps [C].
- **Collision response**: the push does not feed back into the previous point. Only the length step does that, through its weight term [C].

**The rate and the 24 Hz clock**: Poll takes `rate = ThePostProc(DAT_828D0FA4)->emulate_fps (+0x150)` when the hair's directory is a Character (RTTI 0x82886F18) or the class at RTTI 0x82886CD4, and the rate is > 0. Otherwise the rate is 60 (DAT_8202413C) [C]. It skips the step, placing only (0x82336300), when TheTaskMgr's DeltaSeconds is 0 [C].
- The rate changes **only gravity** (scaled by `60 / rate^2`). Stiffness, inertia and friction are per step and not rescaled [C]. It never changes a substep count [C].
- Under ProFilm (24) a step's gravity is `-0.4019 * g`; at 60 it is `-0.0643 * g`.
- That RB polls the band once per paced world frame (24 a second), not once per 60 Hz frame, is [I] (D55).

**Reset** (`reset_hair`, Character 0x822E5780 sets every hair's +0x40 to 1; hookup sets it to 1 too):
- 0x82336F70 rebuilds the chain from the root parent's world times each bone's **local** transform. It zeroes the velocities and sets the last point to `end + y * length`.
- It then runs `+0x40` steps (1) at **rate 15** (0x402E000000000000), with inertia (+0x18) and friction (+0x24) zeroed and then restored [C].
- `band_objects.dta:548` sends a bare `reset_hair` on `teleport_char`. RB2 DX's "35" is DX's own number. RB1 does not pass 15 [C].

## Objective check

Add a `bandcheck: hair <slot>` line in the member loop at rb_band.cpp:1041, printed beside `<slot> stretch` (rb_band.cpp:1405), over 60 s of a song with `GD05_BANDCHECK=1`:
- After the hair poll on each world frame, for every point with collides, compute its penetration in RB's terms: `pen = (point.radius + c.worldRadius) - distance(pos, shape)`, where the shape is the centre for a sphere and the clamped x segment for a capsule. Count it only when `pen > 0`.
- Print p99 and max penetration per member, the points and frames counted, and the number of (point, collide) pairs the hookup made.
- **Pass**: max `pen <= 0.01`. RB pushes each listed point exactly to `inner` in the same step.
- **Info, same line**: penetration of every hair point against **all** of the member's collides, not only the hooked ones. Also the same measure at segment midpoints. RB does not test either of these, so they show where hookup flags or segments let hair through as RB does, not port faults.
- Today the line would read 0 hooked pairs for every member, because of difference 1.
