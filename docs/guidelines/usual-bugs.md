# Usual bugs

Bugs that came back more than once. **They must never happen again**: check
for each of them before anything leaves the machine (owner, 1.1.13). Add a
bug here when it shows up a second time, with how to catch it.

| Bug | How it happened | How to catch it |
|---|---|---|
| The universal launcher released without a game module ("This launcher build has no gd-game-NN module") | A packaging step failed quietly (`set -e` swallowed by a subshell; gdul 0.1.1 shipped without gd02 on Windows) | `gd-engine-launcher/scripts/build.sh all` ends with `verify: ... complete (N game module(s) with their libraries)` for every platform; the release workflow runs `verify_bundle.sh`. Never ship a package without that line |
| The launcher cannot load ISOs, especially on Android and Windows | Path / handle differences: Android content URIs (SAF), Windows wide paths and drive letters. Windows (found 11-09): the launcher recognised a disc through SDL (UTF-8) but the games opened it with `std::fopen`, which reads the ANSI code page, so a disc under a user folder with an accent or with a non-ASCII name did not load | Load an ISO **and a CHD** (GDUL-030: `chdman createdvd`) through **Load ISO** and from `original_isos/` on every platform before a release; the ISO probe self-test (gdcore_selftest `platform_disc_chd` too); on Linux, run `--iso` and a drop with a path holding spaces, accents and brackets. Open user paths with SDL_IOFromFile, or `_wfopen` of the UTF-8 path on Windows (each game's `RandomFile::open`; a CHD opens through gd-engine-core's `RandomAccessFile::open`, which takes every path kind), never a bare `fopen` / `std::ifstream` of a UTF-8 string on Windows |
| Black frames between screens (intro to menu, press-start, song end) | A render target made mid-frame unbound the frame's target; empty frames presented (gd04 GD04-087 / 089) | gd04's `probe:black` / `check:no_black` walk acts; look at the frame probe on new transitions |
| Menus off their highlights | Layout rules not matching the original's (GH3's VScrollingMenu, VMenu width) | Walks with `check:centrex` / `check:pos`; compare with the original's scripts, not by eye |
| A real controller plugged in breaks the self-tests' device counts | The tests count devices; a physical guitar adds one | Run the self-tests with `SDL_GAMECONTROLLER_IGNORE_DEVICES` / `SDL_JOYSTICK_IGNORE_DEVICES` set to the plugged device |
| A full-history secret scan stops a release on old docs | gitleaks scans every commit on a manual run; docs that name secrets look like keys | `.gitleaksignore` holds the reviewed false positives; never write values of secrets in docs |
| Micro stutter when loading a song, a character or a venue | The load (milo parse, texture decode and upload, audio decode, band characters) runs inside one frame on the main thread: gd05 wave 05 measured a 2.4 s frame as game_screen starts (venue 0.5 s, track 0.1 s, band 1.8 s) | Measure every load with a hitch log (gd05: `GD05_HITCHLOG=<ms>` logs each frame over the budget with its screen, and the longest at exit) during a walk that loads a song, a character and a venue. Rule for every game: parse and decode on a loader thread, upload a bounded amount per frame, start the load on the loading screen so it keeps animating; never load in the frame that shows gameplay |
| **Band, characters, menus or venue too dark / near pitch-black** (the lighting engine ported wrong) | Keeps recurring (GH2 transparent + too-dark chars and menus that darken after a song; GH3 dark chars/menus; Rock Band whites not white / wrong grays; Metallica wrong UI colours; **Aerosmith gd06 band near pitch-black — face luma ~3–11 vs original 150–170**; World Tour the same). Two root causes found on gd06: (1) the GH3-engine character shader's lighting registers (ambient, dir lights, the L1 SH probe) not driven by the venue's group lights, so the band is unlit; (2) a **self-shadow** bug — the band *received* its own guessed-direction shadow, so a performer's hair/head blackened their own face (fixed by having the band *cast* into the shadow map but not *receive* its own; `GD06_BAND_SHADOW_LEGACY=1` reverts). **The Xbox 360 display-gamma ramp `709(sRGB⁻¹(v))` is validated against a real console capture — never "fix" darkness by raising global brightness/gamma/exposure; find the real lighting cause.** | Capture the band and the menu from the original (Xenia is authorised per game; store under `~/.local/share/gd-engine/refcaps/gdNN/`) and compare **objectively**: a lighting walk that measures mean luma of the singer/guitarist faces and of menu text vs background against the reference numbers (expected-vs-measured, never by eye). Check the character shader's lighting registers are filled from the venue group lights; check menu exposure/colour is reset when returning from a song |
| **Physics wrong on hair, cloth, accessories** (clipping, wrong gravity) | Physics-driven hair / clothes / accessories pass *through* the body or other objects (colliders missing or off), gravity/response tuned so hair moves at the wrong speed, or clothes overlap skin (World Tour GW-009 hair "100% wrong", GW-010 clothes inside the character) | A physics/ragdoll walk that holds the band on screen through real motion (headbang, strum, star power) and checks for **penetration** (hair/cloth verts inside the head/torso collider) and for settle behaviour against the original; confirm the head and torso colliders are built and enabled; compare hair-motion timing to a reference clip, don't eyeball |
| **A menu that isn't fully mouse-clickable, is mis-framed, or uses a generic font** | Not every menu obeys the universal rules: some options/legends aren't clickable (pause and sub-menus missed — Metallica GM-006, World Tour GW-004), menus are mis-aligned / zoomed-out / offscreen (World Tour GW-001/002), or a **generic font** is used instead of the game's designed font | When the mouse is enabled EVERY option and legend in EVERY menu (main, pause, song-select, options, modal prompts) must have a working hit rect — a mouse-hit walk over each menu asserting it; a framing check that each menu's items sit inside the 16:9 safe area; assert the game's own shipped font is the one in use (no fallback). See `universal-menus.md` for the rules |
